# 样本C 注入问题说明(标准普调与审核流失专题)

> 数据:`赔付样本C_标准普调与审核流失.csv`(18,460 行, 2025-09-01 ~ 2026-08-31)
> 生成:`python sample_data/gen_more.py`(seed=11)
> 验证报告:`sample_data/C_体检报告.md`

| # | 注入的问题 | 实测检出(2026-09-04) |
|---|---|---|
| 1 | 2026-07-13 周**全部赔付金额×1.45**(模拟赔付标准普调: 单量不变、单均普涨) | ✅ 趋势: 周(07-13)+38.3%; 量价拆解: **单量效应仅 4.3%、单均效应 95.7%** —— 一眼可辨"普调/标准变更"形态; 归因按原结构分摊(主因落在基数最大的原因/渠道) |
| 2 | 审核环节通过率压至 62%(模拟规则收紧误伤/审核人力不足) | ✅ 漏斗: 环节3「审核通过」转化率 61.9%(流失 38.1%), 标记为异常; 整体通过率 53.9% |
| 3 | 3 条状态脏值「已赔付」(不在漏斗环节取值内) | ✅ "另有 3 条记录的状态不在漏斗环节取值内, 未纳入漏斗" |
| 4 | 3 条负数、20 条零金额、3 条金额空、4 条用户ID空 | ✅ 全部检出并给出明细 |
| 5 | (对照)不注入任何重复赔付/高频/完全重复/极端大额 | ✅ "未发现同订单重复赔付"、"未发现高频行为"、极端大额 0 条 —— **无误报** |

**样本设计意图**: 采用「干净对照组 + 两类特定问题」的结构: ① 赔付标准普调 —— 验证工具能否通过量价拆解判断为单均普涨而非单量激增; ② 审核环节流失 38% —— 验证漏斗能否及时标记。同时本样本刻意不注入重复赔付、高频行为与极端大额, 用于检验误报: 工具应如实输出「未发现」, 而不是为了显得有用而乱报。
